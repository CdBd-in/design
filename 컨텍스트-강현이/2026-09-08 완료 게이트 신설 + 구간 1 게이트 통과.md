## 1부 — 왜 「게이트」를 만들었나

### 반사실(counterfactual) A/B — 판독의 효용을 숫자로 증명

같은 작업 지시(*"Figma 시안대로 카드 좌우 40px 여백 맞춰줘"*)를 **판독 전 사양서**와 **판독 후 사양서**를 가진 두 세션에 각각 시켰다. (판독 전 문서는 git `dd66884`에 그대로 있음)

| | 판독 전 | 판독 후 |
|---|---|---|
| 판정 | ❌ **"구현 불가"** | ✅ 가능 |
| 산출물 | 값 없음 | 외부여백 **상0 하0 좌40 우40** |
| 디자이너 회신 | *"풀블리드로 **시안을 수정**해주세요"* | *"시안 그대로 재현 가능합니다"* |
| 확신도 | **높음** (틀린 확신) | 중상 70% |

→ **가능한 작업을 불가로 판정하고, 확신을 붙이고, 디자이너에게 시안 수정을 요구했다.**
`cdbd-templates/컨텍스트: 이선호/2026-09-07`이 기록한 실제 사고(*"「CdBd에선 불가능」이라 적어두고 그 전제로 시안을 갈아엎었다"*)와 같은 유형이 **통제된 조건에서 재현**된 것.

### 판정 21건 분류 (구간 1·2)

| 분류 | 건수 | 막는 것 |
|---|---:|---|
| A. 문서가 틀렸고 영상이 정정 | 9 | 앞으로 틀릴 것 차단 |
| B. 문서가 맞았고 영상이 확인 | 8 | **맞는 걸 버릴 뻔한 것 차단** ← 9/7 피해 유형 |
| C. 문서에 없던 신규 | 4 | 몰라서 못 쓰던 기능 |

### 게이트 = 「작동 방식을 안다」와 「실행할 수 있다」를 분리

```
촬영 → 판독 → 정본 반영 → [1단계: 문서 테스트] → [2단계: 실제 에디터] → 다음 구간
                            새 세션이 맞게 답하나    내가 실제로 조작되나
```
게이트 미통과 시 **다음 구간을 찍지 않는다.** 반영이 안 되는 채로 영상만 쌓는 게 가장 비싸다.

## 3부 — 2단계(실제 에디터)에서 나온 진짜 성과

**테스트 페이지 `cdbd.in/editor/6178`** (「CdBd 전 기능 테스트」·멀티 2P·카드 3장). 앞으로 게이트는 이 페이지에서 돌린다.

### 🚨 드라이버 실제 결함 2건 (문서 테스트로는 절대 못 잡는 것)

| # | 결함 | 내용 |
|---|---|---|
| **1** | **`reorderCard`가 페이지를 건드림** | `_sortableCtx()`가 `document.querySelector("[aria-roledescription=sortable]")`로 **DOM 첫 번째** sortable을 잡는데, 멀티페이지에선 **페이지 사이드바 목록이 먼저** 나온다. → **카드가 아니라 페이지 순서를 바꾸고 `moved` 반환** (거짓 성공보다 위험한 *조용한 오작동*). 룩북·카탈로그가 전부 멀티페이지라 실제 작업에서 터질 수 있었음 |
| **2** | **`pinTo` 거짓 성공** | 상단/하단 자리가 차 있으면 「고정 카드 교체하기」 모달이 뜨고 고정 안 되는데 `pinned:top` 반환 |

### 필드명 실측 정정

| 문서가 쓰던 것 | 실제 |
|---|---|
| `block.isShow` | **존재하지 않음** → **`block.disabled`(반전)**. `disabled:true` = OFF |
| `block.fixedPosition` | **맞음** — 단 **고정된 뒤에만 생기는 필드**(미고정 시 undefined) |

block 실제 키: `id, type, style, title, active, disabled, content, previewText, colorPicker, backgroundImage, (고정 시)fixedPosition`

### 여백 자동화 — 유일한 커밋 경로 확정

```js
window.__cdbd.openSpacing('외부여백')                        // sleep 2
window.__cdbd.setSpacing('외부여백',{상:0,하:0,좌:40,우:40})  // sleep 3
window.__cdbd.blockOfRow(window.__cdbd.boardRows()[i]).style.margin  // → "0px 40px"
```
내부 = native value setter → **React `props.onChange`** → **React `props.onBlur`**.
⚠️ **`onBlur`를 빼면 필드엔 값이 보이는데 커밋되지 않는다**(리로드 시 유실).
❌ 실패: `new Event('input')` dispatch · `el.blur()` · Tab · 다른 필드 click · `$B fill` · 슬라이더(`onChange` prop 없음) · PointerEvent 드래그
🚨 **검증 시 `getComputedStyle().margin`은 항상 `0px`** — 제품이 외부여백을 **부모 슬롯의 `padding`**으로 렌더하기 때문. `block.style.margin`을 볼 것.

### 여백 = 실제 CSS 매핑 (실측)

| 계층 | 폭 | padding | 정체 |
|---|---:|---|---|
| 카드 슬롯 | 364 | 40/40 | ← **외부여백** |
| 배경 박스 | **284** | 0 | 배경 |
| 배경 박스 안쪽 | 284 | 20/40 | ← **내부여백** |
| 텍스트 | **204** | 0 | |

가로 364 →(외부40×2)→ 284 →(내부40×2)→ 204 · 세로 222 →(외부40×2)→ 142 →(내부20×2)→ 102
> **둘 다 정상 작동.** 「카드 간 통일 8항목」 #1과 Figma→CdBd 매핑 룰 전부 유효. 충돌 #5 종결 유지.

## 4부 — 🚨 내가 저지른 오류 5건 (같은 실수 방지)

> **모두 「내가 시도해서 안 됐다 = 안 된다」로 건너뛴 것.** 진짜 결함 1건(`reorderCard`)은 오히려 내가 **「성공했다」고 믿은** 쪽에 숨어 있었다.

| # | 내가 적었던 것 | 실제 | 원인 |
|---|---|---|---|
| ① | 외부여백 좌우 **렌더 미반영** → 정본 수정 + 충돌 #5 재개까지 함 | 정상 작동 | 내부·외부가 **둘 다 40**이라 구분 불가인데 단정. CSS `margin`을 찾았으나 제품은 **슬롯 `padding`**으로 구현 |
| ② | `fixedPosition` 필드 **없음** | 고정된 뒤에만 생김 | 미고정 카드만 보고 결론 |
| ③ | **여백 자동화 불가** | 가능 | **정본에 방법이 있었다** (`cdbd-templates/.claude/cdbd-edit-shared.md:22` — *"필드 커밋 = blur 필요"*). 그 파일을 안 읽고 4가지 시도 후 결론 |
| ④ | 이미지 업로드 **결함** | 문서화된 정상 동작 | `agents/editor-s4-image.md:30` — 채워진 카드는 `openImageUpload` 무효, **38×38 오버레이 fiber onClick** 경로 |
| ⑤ | 미리보기 **수동** | `goto viewer?refresh={ts}` 가능 | **내가 이미 성공해놓고** 👁 버튼이 안 눌린다는 이유로 🔴 |

### 🔑 그래서 게이트에 박은 규칙

**「🔴 안 된다」는 3단계를 다 거쳐야 확정. 하나라도 빠지면 `❓ 미확정`으로 적는다.**
1. **정본 검색** — `grep -rn "<기능명>" cdbd-templates/.claude cdbd-design-service` (특히 `cdbd-edit-shared.md`·`agents/editor-*.md`·`SKILL.md`)
2. **변수 분리** — 관련 값을 **서로 다르게** 놓고 재측정
3. **사용자 확인** — *"이거 원래 되던 거 아닌가요?"*

**✅(된다)도 반환값만 보고 적지 않는다. 반드시 리로드 후 상태를 다시 읽어 확인.**

### 🔬 촬영 지시서에도 반영: 「한 번에 한 변수만」

원 판독(9/4)이 영상 1-5에서 **내부여백 120 + 외부여백 200을 동시에** 설정한 화면을 보고 좁아진 것을 외부여백으로 귀속한 것, 그리고 내가 ①에서 같은 교란을 밟은 것 — **두 번 다 「두 값이 같거나 동시에 바뀌어 원인을 못 가른 것」**.
> 영상은 **「무엇이 보이는가」**만 말한다. **「무엇 때문인가」**는 변수를 하나씩 끊어야 나온다.
