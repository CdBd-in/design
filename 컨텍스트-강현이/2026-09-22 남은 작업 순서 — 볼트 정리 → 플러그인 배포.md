## 🔑 이번에 확정된 것 3가지

### ① 플러그인은 만들지 않는다 → `design/CLAUDE.md` 신설로 대체

데스크탑 `CdBd 기능 문서 구조 설계.pdf` p.13이 든 플러그인의 이유 3가지를, **팀원이 `design` 저장소를 clone해서 쓰는 조건**에서 다시 보면:

| 플러그인이 하는 일 | clone 조건에서는 |
|---|---|
| 어느 볼트·맨 바깥에서 켜도 로드 | 저장소 밖에서 켤 땐 `~/.claude/CLAUDE.md`에 `@import` 한 줄이면 같은 효과 |
| 마켓플레이스 자동 최신화 | `git pull`이 동일. 스킬은 어차피 볼트 안에 있어 pull 필수 → 경로가 둘이면 「정답이 둘」(PDF p.4) 재발 |
| 볼트를 넘는 라우팅 | **Claude Code는 상위 폴더 `CLAUDE.md`를 자동 로드.** `design/CLAUDE.md`가 **없어서** 안 되던 것 |

**배포 대상** — 선호님·명우님. 한 분은 design 볼트 공용, 다른 한 분은 GitHub만 공용이나 **CdBd를 실제로 조작**함 → 스킬(`cdbd-templates/.claude/skills/`)이 필요 → **`design` clone 필수** → 플러그인 무의미.
→ **결정: 플러그인 폐기.** 통합 가이드는 허브에 두고 `design/CLAUDE.md`로 로드. 나중에 「GitHub만 같은 사람」이 3~4명으로 늘면 허브의 통합 가이드를 `cdbd-plugin`으로 옮긴다(45분).
→ 실행 계획서 §8 · 9/21 노트 ⓑ「플러그인 미착수 0%」는 **이 결정으로 종결.** 계획서 status 줄 갱신 필요(아래 12번).

### ② 원본 영상 — 「구간 3·4 소실」은 사실이 아니다

9/21 노트의 「구간 3·4 소실 · 구간 2는 3/15 잔존」은 **다른 기기 기준**이었다. 이 맥(`g1-Mac.local`) `~/Desktop/CdBd 기능 녹화 영상/`:

| 폴더 | 파일 | 용량 |
|---|---:|---:|
| 구간 1 | 8 | 253MB |
| 구간 2 | 23 (2-1~2-15 전부 + 보충) | 3.5GB |
| 구간 3 | 11 | 398MB |
| 구간 4 | 8 | 216MB |
| 구간 5 | 4 | 454MB |
| **계** | **54** | **4.8GB** |

구간 6~10은 이 맥에 없다 → 다른 기기. **지우지 말고 구글 드라이브에 구간별 폴더째, 기기별 하위 폴더로** 올린다(같은 폴더명이 두 기기에 있어 합치면 덮어씀). PDF p.18과 동일 방침: 정본 = 텍스트 · 원본 = 드라이브 · 핵심 프레임 = 볼트.

### ③ 플러그인 범위 논쟁도 함께 종결

PDF p.14(가이드 한 장) vs 계획서 §8(스킬까지)이 달랐으나, 플러그인 자체를 안 만드니 **논점 소멸.** 다만 「스킬은 볼트에 묶여 있어 떼면 참조가 깨진다」(PDF p.5)는 원칙은 유지 — 스킬을 볼트 밖으로 옮기지 않는다.
