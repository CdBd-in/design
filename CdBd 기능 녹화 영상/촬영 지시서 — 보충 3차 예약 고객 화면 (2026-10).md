## 준비

### 기기 2대
| 역할 | 기기 | 녹화 |
|---|---|---|
| **고객** | 휴대폰 A (문자를 받는 실물 폰) | 폰 자체 **화면 기록**(iPhone 제어 센터 · Android 빠른 설정) |
| **호스트** | 휴대폰 B **또는** PC | 폰 B 화면 기록, 또는 PC `Cmd + Shift + 5` |

> 🚨 **호스트를 PC 웹캠으로 하면 촬영자 얼굴이 찍힌다**(8-4 사고). 폰 B의 **후면 카메라**로 스캔하는 쪽을 권한다. PC를 써야 하면 웹캠이 고객 폰 화면만 보도록 각도를 잡는다.

### 테스트 페이지 설정 (본인 전용 · 이미 URL이 있는 페이지)
예약 카드 「예약 정보 관리하기」에서:

1. **필수 정보** — 제목 `촬영 테스트 예약` · 장소 `테스트` · 호스트 이름 `촬영 호스트` · 호스트 연락처는 호스트 역할 폰 번호
2. **예약 옵션 2개** — 둘 다 **오늘 날짜** · 시간만 다르게 · **옵션 1은 인원 제한 1명**(정원 초과 확인용) · 옵션 2는 5명
3. **방문 체크 가능 시간** — 시작 = **촬영 시작 30분 뒤** · 종료 = **오늘 23:59** (시간 밖 화면과 시간 안 화면을 둘 다 찍으려고)
4. **중복 예약 허용** — **꺼짐**(기본값 그대로)
5. **예약자 인증 정보** — 추가 문항 1개(객관식 · 필수)
6. 설정한 뒤 **게시본에 반영됐는지 먼저 확인**한다. 게시 버튼에 금액 모달이 뜨면 멈추고 보고한다.

### 녹화 규칙 (구간 11과 같음)
- **[정지]** = 그 화면에서 2~3초 완전히 멈춤. 판독은 정지한 프레임으로 한다.
- 각 클립 첫 3초는 가만히 · 누른 뒤 1~2초 정지 · **한 번에 한 동작**
- 소리는 판독하지 않는다. 설명이 필요하면 메모 앱에 타이핑한다.
- 파일명 `12-1_예약하기_고객폰.mp4` 형식 · 업로드 = 드라이브 `help@cdbd.in › CdBd 기능 녹화 원본/구간 12/`
- **두 기기를 함께 찍는 클립(12-5·12-6)은 두 영상을 같은 시각에 시작**하고, 시작할 때 두 화면을 한 번씩 서로에게 비춰 맞춘다.

### 개인정보
- 예약자 이름은 `촬영테스트1`, `촬영테스트2`처럼 넣는다.
- 고객 폰의 **문자 앱 · 알림**에 다른 대화가 보이지 않게 한다(방해 금지 모드 켜기 · 문자 목록 대신 해당 대화만 열기).
- 전화번호가 보이는 프레임은 보존할 때 가린다 — 원본 영상은 **팀 밖 공유 금지**.

## 1순위 — 고객 흐름 (예약 ① · 7C)

### 12-1. 예약하기 — 카드에서 완료 화면까지 (고객 폰 · 약 3분)
**왜** 고객이 실제 폰(360px 근처)에서 보는 예약 카드와 인증 과정을 처음부터 끝까지 확보한다. 지금은 인증번호 입력 단계에서 끊겨 있다.

1. 문자·카톡 등으로 받은 페이지 주소를 폰에서 연다 → 예약 카드까지 스크롤 [정지]
2. 예약 카드에서 **옵션 2개가 어떻게 보이는지** [정지] → **옵션 1**(정원 1명) 선택 [정지]
3. 「본인 인증하기」 창 [정지] → 이름 · 추가 문항 입력 [정지]
4. [인증번호 받기] → **문자 앱 알림이 뜨면 그대로 [정지]**(인증번호 문자 전문)
5. 인증번호 입력 → [다음] → 그다음 나오는 화면마다 [정지] (확인 단계가 더 있는지)
6. **「예약 완료」 화면** — 위에서 아래까지 천천히 [정지] (QR이 여기에 보이는지 · [예약 취소] · 공유 버튼)

**영상에 반드시 보여야 할 것**
- 옵션 2개가 표시된 예약 카드 · 인증 창 전체 · 인증번호 문자 전문
- [다음] 이후의 모든 화면 · 「예약 완료」 화면 전체

### 12-2. 예약 완료 문자 → 링크로 다시 열기 (고객 폰 · 약 2분)
**왜** 고객이 나중에 예약 내역과 QR을 어디서 다시 여는지 모른다. 「예약 현황 링크」가 문자에 들어 있는지부터 확인해야 한다.

1. 예약 직후 문자 앱 → 받은 **예약 완료 문자** 전문 [정지] (안 오면 1분 기다리며 [정지] · 안 오면 「안 옴」을 메모 앱에 타이핑)
2. 문자 안 링크를 누른다 → 열리는 페이지 [정지] — 브라우저가 무엇인지(사파리·크롬·문자 앱 안) 보이게
3. 그 페이지에서 **다시 인증을 요구하는지** [정지]
4. 브라우저 탭을 닫고 **처음 페이지 주소(예약 카드)** 로 다시 들어간다 → 예약 카드가 「이미 예약함」 상태로 바뀌어 보이는지 [정지]

**영상에 반드시 보여야 할 것**
- 예약 완료 문자 전문(보낸 번호 · 링크 주소 포함) · 링크로 열린 첫 화면 · 재인증 여부

### 12-3. 방문 체크 가능 시간 **전** 고객 화면 (고객 폰 · 약 1분)
**왜** 호스트 쪽은 시간 밖이면 「방문 체크 가능 시간이 아닙니다」가 뜨는 것까지 확인했다. 고객 쪽은 QR이 숨는지, 안내가 뜨는지 모른다.

> ⏱ 방문 체크 시작 시각(촬영 시작 30분 뒤) **전에** 찍는다.

1. 12-2의 링크(또는 예약 완료 화면)를 연다 → QR 자리 [정지]
2. 호스트 기기에서 `/host`를 열어 「방문 체크 가능 시간이 아닙니다」 [정지] (같은 시각 비교용)

**영상에 반드시 보여야 할 것**
- 시간 전 고객 화면 전체(QR이 있는지 · 안내 문구 · 버튼 비활성 여부) · 화면 위 시계

### 12-4. 고객 QR 화면 — 갱신되는지 (고객 폰 · 약 2분)
> ⏱ 방문 체크 시작 시각이 **지난 뒤** 찍는다.

1. 고객 폰에서 QR 화면을 연다 [정지]
2. **손대지 말고 70초 이상** 그대로 둔다 (QR 무늬 · 남은 시간 표시 · 새로고침 버튼이 있으면 그 변화)
3. QR 아래에 **[완료하기]** 가 있는지 [정지] — **아직 누르지 않는다**

**영상에 반드시 보여야 할 것**
- 70초 이상 끊김 없는 QR 화면(갱신되면 그 순간 포함) · QR 아래 버튼 · 화면 위 시계

### 12-5. 스캔 → 고객 [완료하기] → 완료 (두 기기 동시 · 약 3분)
**왜** 판정 158의 호스트 문구 「QR 코드 아래의 완료하기 버튼을 눌러 방문 체크를 완료해 주세요.」대로 **고객이 버튼을 눌러야 끝나는지** 확정한다.

1. 호스트 `/host` → [📷 카메라로 QR 스캔하기] → 고객 QR 스캔
2. **스캔 직후 두 화면 각각** [정지] — 고객 화면이 바뀌는지 / 그대로인지
3. 고객 폰에서 **[완료하기]** → 확인창이 있으면 [정지] → 완료 후 고객 화면 [정지]
4. 호스트 화면이 「5초 후 처음 화면으로」 돌아간 뒤 상태 [정지]
5. PC에서 예약 현황 목록 → **새로고침 전** [정지] → 새로고침 후 「방문 완료」 · 방문 일시 [정지]
6. 고객 폰에서 12-2 링크를 **다시 열기** → 방문 완료 뒤 고객 화면 [정지]

**영상에 반드시 보여야 할 것**
- 스캔 직후 두 기기 화면 · [완료하기] 누르기 전·후 고객 화면 · 목록 새로고침 전·후 · 방문 완료 뒤 링크 재접속 화면

### 12-6. 스캔 실패 화면 (두 기기 · 약 2분 · 추가 비용 없음)
1. **방문 완료된 QR을 다시 스캔** → 호스트·고객 화면 [정지]
2. 12-4에서 QR이 갱신됐다면 — **갱신 전 QR을 찍어 둔 스크린샷**을 스캔 → [정지]
3. 다른 페이지의 `/host`로 이 QR을 스캔할 수 있으면 → [정지] (없으면 생략)

**영상에 반드시 보여야 할 것**
- 실패할 때 호스트 화면 문구 전문 · 고객 화면 변화

## 2순위 — 취소와 막힘 (예약 ② · 7C)

### 12-7. 고객이 직접 예약 취소 (고객 폰 · 약 3분)
1. **다른 번호의 폰**(호스트 역할 폰 B 등)으로 **옵션 2** 예약 ②를 만든다 — 12-1과 같은 순서지만 [정지]는 완료 화면에서만
   - 🔑 같은 폰 A로는 하지 않는다 — 중복 예약이 꺼져 있어 막힐 수 있고, 그 장면은 12-8 몫이다
2. 「예약 완료」 화면 또는 문자 링크 → **[예약 취소]** → 확인창 전문 [정지] (커서·손가락은 [취소하기]·닫기 쪽에 둔 채)
3. 취소 실행 → 취소 후 고객 화면 [정지]
4. 문자 앱 — **취소 문자가 오는지** [정지] (1분 대기)
5. PC 예약 현황 새로고침 → 상태 · 방문/취소 일시 [정지]
6. 같은 링크를 다시 열기 → 취소된 예약 화면 [정지]

**영상에 반드시 보여야 할 것**
- 취소 확인창 전문 · 취소 뒤 고객 화면 · 취소 문자 유무 · 호스트 목록의 상태 변화

### 12-8. 막히는 경우 2가지 (고객 폰 · 약 3분 · 0C 예상)
> ⚠️ 막히지 않고 예약이 성립하면 **건당 7C**가 나간다. 그래도 결과 자체가 판정 근거이니 화면은 끝까지 찍는다.
