# 🔴 판독 전제 — **실기기가 아니라 Chrome DevTools 에뮬레이션이다**

> 📎 `10-0_전제_DevTools에뮬레이션_GalaxyS8+_360x740.jpg`

전 클립 상단에 **`Dimensions: Samsung Galaxy S8+ · 360 × 740 · 85% · No throttling`** 툴바와 **DevTools 패널(Elements/Console/Styles)** 이 열려 있다.

> 지시서 요구: *"**모바일 기기**에서 화면 녹화(iOS 제어센터 · Android 화면 기록)로 찍어주세요."* → 🔴 **미충족**

**무엇이 확인되고 무엇이 안 되는가**

| 확인 가능 ✅ | 확인 불가 🔴 |
|---|---|
| **CSS 미디어쿼리 기반 반응형 분기** — 레이아웃·요소 유무·배치 | **실제 터치 제스처**(스와이프·핀치·롱프레스) |
| 텍스트·버튼·모달 **원문** | **모바일 브라우저 크롬**(주소창 자동 숨김, 하단 툴바, safe-area) |
| 데스크탑 전용 차단 로직 | **실기기 성능**·폰트 렌더·스크롤 관성 |
| 요소의 `aria-label` 등 내부 속성(DevTools 덕분) | **iOS vs Android 차이** |

> 🔑 **이 구간의 판정은 전부 「360px 폭에서의 반응형 분기」로 한정해 읽어야 한다.** 「모바일에서 이렇다」가 아니라 **「360px 뷰포트에서 이렇다」**가 정확한 서술이다.
> 📌 **⏳ 실기기 재촬영을 보충 목록에 등록한다** — 다만 **P3**. 반응형 분기 자체는 이 영상으로 충분하고, 실기기에서만 달라지는 건 제스처·브라우저 크롬 정도다.

# 판정 98 — 모바일 홈·내 계정 = **로고 드롭다운이 햄버거 드로어로** (10-1·10-9)

> 📎 `10-1_모바일홈_충전[+]아이콘·「오늘 만료」경고바.jpg` · `10-1_햄버거드로어.jpg` · `10-9_내계정_「계정 삭제하기」_모바일에도_유지.jpg`

## 홈 (위→아래)

| 요소 | 실측 |
|---|---|
| 상단바 | **CdBd 로고**(좌) · 🔑 **☰ 햄버거**(우) — 데스크탑의 **로고 드롭다운이 드로어로 바뀐다**(홈/내 페이지/내 계정…) |
| 인사 | CdBd 로고 + 「안녕하세요, **{이름}**님」 |
| 계정 배지 | 👤 `{이메일}` |
| **크레딧 바** | 🪙 **`870,722 C │ 0 P`** + 🔑 **[+] 아이콘 버튼** ← ✅ **지시서 10-1의 답: 「충전하기」가 [+] 아이콘으로 바뀐다** |
| 🆕 **만료 경고 바** | **`오늘 만료 · {페이지명} · https…`** + **[연장]** ← 🔑 **구간 4 지시서 4-1 ④**(*"만료 임박 URL 연장 영역이 있는지"*)가 **여기서 처음 관측**됐다 |
| 2열 버튼 | **[새 페이지 만들기]** / **[내 페이지 전체]** (아이콘 + 라벨) |
| 하단 | **「가장 최근에 수정한 페이지에요」** + 카드 |

## 내 계정 (10-9)

데스크탑과 **동일한 4영역**(계정 정보 / 크레딧 / 배포 정보 / 연동 정보)이 **1열로 쌓인다.**

> ✅ **지시서 10-8의 답 — 「계정 삭제 항목이 사라지는지」 = 사라지지 않는다.** 계정 정보 우측에 **[계정 삭제하기]**가 그대로 있고, 눌러 **설문 모달**까지 정상 진입한다.
> ✅ **[충전하기]·[결제 내역]·[이용 내역]·[변경하기]** 전부 유지 — 크레딧 결제/이용 내역 모달도 **모바일에서 열린다**(표는 1열로 좁아짐).
> ✅ **「내 주소 변경하기」 모달**도 동일 — 「50 크레딧이 차감되며, 내가 만든 모든 페이지 주소가 일괄 변경됩니다」
> 🔑 **연동 정보 [연동하기] → 네이버 커머스솔루션마켓**으로 이동하는 것도 동일(판정 95).

## ⏳ 미확인
- **햄버거 드로어 항목 전체**(데스크탑 5항목과 같은지)
- 만료 경고 바가 **며칠 전부터** 뜨는지(실측은 「오늘 만료」 1건)

# 판정 99 — 내 페이지 = 🔑 **호버가 없으니 아이콘이 「항상 노출」된다** (10-2)

> 📎 `10-2_내페이지_✏️·⋯·QR_항상노출.jpg`

| 요소 | 실측 |
|---|---|
| 상단바 | 로고 · **「내 페이지」** 제목 · **[새 페이지]**(보라) |
| **탭 3종** | ✅ **상단 세그먼트 유지** — 내가 만든 / 저장한 / **초대받은 페이지** |
| **필터 칩** | ✅ 유지 — 전체 / 원페이지 / **멀티페이지** |
| 카드 | **1열** · 썸네일 + 제목 + URL + 만료 |
| 🔑 **액션** | ✅ **지시서 10-2의 답** — 호버가 없으므로 **✏️ 원형 버튼(썸네일 우상단)** · **⋯ 버튼** · **QR 아이콘**이 **항상 보인다** |
| ⋯ 메뉴 | 어두운 오버레이 + **세로 리스트**(복제하기·삭제하기 등) |
| 멀티 배지 | 썸네일 좌상단 **`⚭ 2`** (페이지 수) |

> ⏳ **[통계보기]가 어디로 갔는지 미확인** — 데스크탑은 호버 시 [수정하기]·[통계보기] 2버튼인데, 모바일은 ✏️ 하나만 보인다. **⋯ 메뉴 안으로 들어갔을 가능성**이 높으나 메뉴 항목 전체를 확대하지 못했다.

# 판정 100 — 에디터 = 🔑 **3보드가 「상단 미리보기 + 하단 패널」로 접힌다** (10-3·10-4)

> 📎 `10-3_에디터_상단미리보기+하단디자인패널.jpg`

| 데스크탑 | 모바일(360px) |
|---|---|
| 좌 미리보기 / 중 카드보드 / 우 디자인보드 **3컬럼** | 🔑 **상단 = 미리보기 고정** · **하단 = 카드 목록 ↔ 디자인 패널**이 번갈아 |

> 🔴 **지시서 10-3의 「디자인 보드가 사라지는지」 = 사라지지 않는다.** **하단 시트로 내려온다.**
> 🔴 **「미리보기가 플로팅 버튼인지」 = 아니다.** 미리보기는 **상단에 상시 고정**된다.
> 카드 선택 → 하단이 **「T {카드명}」 디자인 패널**로 전환(텍스트·스타일·슬라이더·색상 피커 전부 동작).
> **[카드 추가하기]** → 전체 모달(세로 리스트/그리드) · **페이지 테마**·**내 테마** 모달도 동일하게 뜬다.

## 멀티 에디터 (10-4)
> ⏳ **지시서 10-4의 「페이지 목록이 전체 모달로 바뀌는지」는 확대 판독을 못 했다.** 클립은 확보돼 있으므로 **재판독으로 회수 가능**(보충 촬영 불필요).

# 판정 101 — 통계 = **요약 카드가 가로로 압축되고 탭은 유지** (10-5)

> 📎 `10-5_통계_요약카드3개_가로배치.jpg`

> 🔴 **지시서 10-5의 「기간 탭이 사라지는지」 = 사라지지 않는다.** 「최근 7일/14일/30일」 + 날짜 입력이 **가로로 좁게 유지**된다.
> **통계 요약 3카드**(페이지뷰·클릭수·클릭률)가 **가로 3분할**로 압축 · 추이 차트·「링크별 클릭」 유지.
> **제출된 답변** — 질문 카드 + **파이 차트가 모바일에서도 렌더**된다.
> **개별 URL 서브탭** — 「URL 개수 / 활용률」 2카드 + 검색 + 테이블 유지.
> ⏳ **다운로드 버튼이 아이콘으로 바뀌는지**(지시서 ③) · **표의 가로 스크롤** 여부는 확대 미실시.

# 판정 102 — 뷰어 = 🆕 **스와이프 안내의 내부 이름이 「스와이프 안내」다** (10-6)

> 📎 `10-6_스와이프안내_aria-label「스와이프 안내 닫기」.jpg`

멀티 뷰어를 360px로 열면 **판정 70의 「페이지 넘김 가이드」가 동일하게** 뜬다 — 화면 전체가 어두워지고 보라 `›››` + **「화면을 오른쪽으로 넘겨 보세요」**.

> 🆕 **DevTools 인스펙터로 내부 속성이 잡혔다** — 그 오버레이는 **`<button aria-label="스와이프 안내 닫기">`** 이고 `background: #000000CC`, `360×740` 전면이다.
> 🔑 **즉 「자동으로 사라지는 안내」가 아니라 「탭하면 닫히는 버튼」**이다. 판정 70은 *"1.5~2초 후 사라짐"* 이라고만 적었는데, **탭으로도 닫을 수 있다**는 게 추가됐다.
> 🔑 **제품 내부 명칭 = 「스와이프 안내」** (설정 라벨은 「페이지 넘김 가이드」). 용어가 둘이다.
> 컨트롤러 바(진행 바 + 카운터 + 아이콘)·좌우 「‹ ›」도 360px에서 유지된다.
> ⏳ **실제 스와이프 제스처**는 에뮬레이션이라 검증 불가.

# 💰 판정 104 — 🆕 **URL 생성(게시) 요금 모달 전문 확보** (10-8)

> 📎 `10-8_URL생성하기_멀티2P_2개월200C·12개월1000C·배너20%.jpg` · `10-8_URL정보편집_상단메뉴(모바일)_ON.jpg`
> ⚠️ **파일명은 「권한 관리」지만 내용은 「신규 생성 → URL 정보 편집 → URL 생성(결제)」 흐름**이다. 권한 관리 화면은 이 클립에 없다.

## 「URL 생성하기」 결제 모달 — 🎯 **요금표가 화면에 있다**

> **「URL 2개월 이용 시 / 총 200 크레딧이 차감됩니다.」**

| 항목 | 실측 |
|---|---|
| 내 크레딧 | `870,722C` |
| 🔑 **이용 기간 선택하기** | ⦿ **2개월 — 200C** (`페이지 당 100C`) / ○ **12개월 — 1000C** (`페이지 당 500C`) |
| 🆕 할인 | ☐ **「CdBd 배너 유지하고 20% 할인 받기」** |
| 내역 | **기본 URL 2개월 200C** / └ 페이지 수 **2페이지** / └ 페이지 당 금액 **100C** |

> 🎯 **사전 §10의 「멀티페이지(페이지당): 2개월 100C / 12개월 500C」가 화면 원문으로 확증**됐다.
> 🎯 **「배너 유지 20% 할인」의 원문 라벨**을 처음 확보했다.
> 🔑 **URL 생성은 이용 기간을 「고를 수 있다」** — 🎯 **개별 URL(기본 URL 만료일까지 자동 결정 · 판정 83)과 정반대**다. **둘을 혼동하면 안 된다.**
> ⏳ **멀티페이지에 「1개월」 옵션이 없다** — 선택지가 2개월·12개월 둘뿐이었다. 원페이지는 영수증에 **1개월 -120C**가 있으므로(판정 97) **유형별로 선택지가 다를 가능성**. 미확정.

## 🎁 부수 — 「페이지 상단 메뉴 (모바일)」 기본값 재확인

신규 문서의 「URL 정보 편집하기」에서 토글 3개가 **비밀번호 OFF / 페이지 상단 메뉴(모바일) 🔑 ON / 사이드바(데스크탑) ON**.

> ✅ 판정 76(원페이지 `6140`)에서는 **상단 메뉴가 OFF**였는데, **신규 문서에서는 ON**이다.
> 🔑 **사전의 「제품 기본값 = ON ↔ 팀 정책 = 항상 OFF」 구분이 옳았음이 확증**됐다. 6140은 **팀 정책으로 꺼둔 문서**였다.
